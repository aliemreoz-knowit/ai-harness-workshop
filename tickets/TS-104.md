# TS-104: After a short dropout the stream never recovers and ends up frozen

**Type:** Bug  
**Component:** daemon / receiver  
**Reported by:** stream operator (projector station)

## Description

A one-to-two-second dropout of the link (cable pulled briefly, or a relay
blackout) should cost one short freeze and then the stream should be back at
30 fps. On the HIL station it does not recover: after the dropout the picture
freezes every few seconds, the viewer's NACK counter stays at 0 although the
relay keeps dropping packets, keyframe requests climb, and after about a minute
and a half the picture stands still. STATS keep arriving and the TCP
connection stays up.

The HIL station starts the daemon with the facilitator start-up option
`--seq-start 65000`; the operators saw the same picture in normal operation,
but only on streams that had been running for several minutes, never right
after a start.

## Steps to reproduce

1. On the Pi: `tinystreamd --source synth --seed 1 --seq-start 65000`
2. On the laptop, a relay scenario file `dropout.txt`:
   ```
   t=2s blackout 2s
   t=5s loss=1%
   ```
3. Start the relay and, right after it, the viewer:
   `tsnetem --listen 0.0.0.0:5620 --forward 127.0.0.1:5610 --peer 10.42.0.2:5600 --scenario dropout.txt`
   `tsrecv --server 10.42.0.2:5601 --udp-port 5610 --announce-port 5620 --seq-start 65000 --seconds 90`
4. Watch `metrics.json` / `frame.pgm` (written every 500 ms).

## Expected

One freeze for the dropout, then ~30 fps for the rest of the run; the 1 % loss
is repaired by NACKs (`nacks_sent` climbs, `freezes` stays at 1), about 2600
frames decoded in 90 s.

## Actual

About 1200 frames decoded in 90 s, ~36 freezes, `nacks_sent` 0 and `loss_pct`
0 for the whole run although the relay drops packets, ~70 keyframe requests;
at the end `fps` is 0-6 and `frame.pgm` hardly changes.

## Environment

- tinystream: the kick-off live stream (also on the ticket branch)
- Pi 5, Raspberry Pi OS Lite 64-bit, direct Ethernet 10.42.0.x, synth source
- Laptop: Ubuntu 24.04, tsrecv + tsnetem built from the same tree
