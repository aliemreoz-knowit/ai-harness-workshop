# TS-104: After a short dropout the stream never recovers and ends up frozen

## Context

tinystream streams frames over UDP and repairs losses with NACKs. A short dropout of the link should cost one freeze.
Reported from the projector station. The operators saw the same in normal operation, but only on streams that had been running for several minutes.

## Steps to reproduce

1. Daemon: `tinystreamd --source synth --seed 1 --seq-start 65000`
2. A relay scenario file `dropout.txt`:
   ```
   t=2s blackout 2s
   t=5s loss=1%
   ```
3. Start the relay with `--scenario dropout.txt`, then the viewer with `--seq-start 65000 --seconds 90` (full command lines in the reporter's ticket).
4. Read `metrics.json`.

## Inputs

The scenario file above, the synth source with seed 1, start sequence 65000.

## Expected

One freeze for the dropout, then about 30 fps for the rest of the run. The 1 % loss is repaired by NACKs:
`nacks_sent` climbs, `freezes` stays at 1, about 2600 frames are decoded in 90 s.

## Actual

About 1200 frames in 90 s, about 36 freezes, `nacks_sent` 0 and `loss_pct` 0 although the relay drops packets,
about 70 keyframe requests. At the end `fps` is between 0 and 6.

## Acceptance criteria

- After a short blackout followed by 1 % loss, the stream has one freeze and `nacks_sent` is greater than 0 (a loopback test, checked by the loopback gate).
- No gate that passes on the base branch fails after the change.
- The change comes with a regression test.
